# Collapse the Action Resolver into the Encounter Engine

`ActionResolver` is gone as a separate module. Action legality and state transitions live inside `EncounterEngine` as private implementation, and the engine's seam is what ADR 0009 documents: `start`, `apply`, `advance_phase`, plus `legality` and `legal_actions` (ADR 0013), plus read projections (`get_hero`, `get_status`, `has_status`, `get_telegraphs`, `board`, and the scene-facing fields). `add_status` remains public as the Probe setup seam for injecting authored Status Effects.

The two files were one module split down the middle: every resolver function took `engine` and mutated it, and nine of the engine's public functions — `put_hero`, `apply_damage`, `consume_statuses_for_slot`, `status_actions`, `hazard_actions`, `evaluate_damage_status`, `remove_status`, `check_resolution`, `next_minion_id` — existed only for the resolver to call back. Nothing else called them, so they are now private, along with the `action_resolver`, `_timeline_resolver`, and `_card_resolver` collaborators. `TimelineResolver` and `CardResolver` remain internal collaborators below the seam; they are implementation detail, not interface.

We chose collapsing over keeping the resolver as an internal-but-separate file because the split forced an inside-out seam — state in one file, rules for that state in the other, connected by a callback surface wider than the real interface — and every widening of that surface invited a caller to reach past `apply`. The `engine_seam` Probe protects the collapsed surface: the documented seam is callable, the callback surface is not, no resolver collaborator or module exists beside the engine, and the load/charge/fire flow resolves through `apply` alone.
