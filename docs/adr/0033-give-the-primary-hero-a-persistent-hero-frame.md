# Give the primary Hero a persistent Hero Frame

The primary Hero gets persistent chrome at the board's bottom edge, in two pieces that read as one machine. The **Hero Frame** is the unit frame an MMO player already knows how to read: the Hero's name attached to a dominant health bar carrying the Armor overlay, with the class resource as a thinner bar directly beneath it — the position mana occupies — plus the Counter chips and deck gauge it absorbed from the hero branch of the Stat Panel. The **Signature button** stands beside the frame as its own plate, and it is on screen only while the Signature can actually be fired: it arrives when the fixed Slot's window opens on an earned Charge and leaves the moment it is spent or the window turns. Firing is a tap on it, through the same store path the Action Bar's Slots use. The decision is D-058; this ADR records what it supersedes and the constraints that keep it honest.

**The frame is read; the button is pressed.** That division is why they are separate objects rather than one, and it is what makes the button's absence safe. The grilling that produced D-058 settled the opposite twice over — one control that was also its own resource meter, permanently on screen — and both halves were rejected once built. A button wedged into a readout made the readout a control surface and left neither shape legible at 390 points; a permanent button then spent that space asserting an offer the rules were denying in three windows out of four. Both idioms this HUD borrows from already draw the line the same way: an MMO keeps abilities on a bar away from the unit frame, and a hero shooter's ultimate prompt is the moment the power becomes available, not furniture that describes its own unavailability.

What the permanent version was protecting survives, because the frame took the job: the resource bar shows the Charges through every window, so an empty meter still teaches the earn and a held bank is still readable in the windows the Signature cannot act in. **That is the load-bearing dependency — appear-when-usable is only honest while the resource stays visible somewhere else.** A future change that removes the bar has to put the button back.

## What this supersedes, and what it turns out not to

**ADR 0006's persistent-button clause stands.** It limits persistent buttons to phase progression and recovery, so that direct manipulation keeps spatial play legible on a phone. The Signature strains the premise — it is an ability with no card to drag, its Charge being earned rather than tucked, and the alternative shipped first (a third Action Bar plate) cost the two real Slots their width on a 390-point ladder — but it does not break the clause, because the control it is fired from is transient. It exists in the window the rules would accept the press and nowhere else, which is a narrower claim on the HUD than the Slot plate it replaced. An earlier draft of this ADR superseded the clause for a permanent button; that supersession is withdrawn. Everything else in ADR 0006 stands — the Bottom Interaction Zone's order (board, Action Bar, Hand), drag-to-prepare, drag-to-charge, tap-to-fire, drag-to-move.

What this ADR does add to the HUD's permanent furniture is the Hero Frame itself: persistent chrome that is read rather than pressed, which ADR 0006 never spoke to.

**The Stat Panel's "temporal, not spatial" identity, deliberately and by half.** The interface direction chose one tap-summoned readout over persistent gauges, and the board direction deferred per-token state until the multi-Hero party model. That tension ("board-first argues for putting it back… resolved deliberately rather than drifted through") is resolved here, on the Hero's side only: *your own* state is chrome, because the Signature made some of it into controls and currency — a resource that fuels an identity ability cannot live on a surface that is sometimes closed, and the bank-versus-cash read (D-057 decision 13) needs the resource bar visible through the windows the Signature cannot act in. The *Enemy's* state keeps the tap-summoned panel unchanged: the difference between reading your own machine and inspecting the thing trying to kill you is now spatial, which is the sharper version of the distinction the panel was built for. Tapping the Hero's tile pulses the frame — the tap points at the chrome that answers it — and never opens a panel.

## The constraints that keep it honest

- **The board never resizes for it.** The frame floats in the board container's spare height — the canvas is width-bound at 390 points and now pins to the container's top, so the spare height pools under the last hex row, which is where the frame and the dock's prompts live. This is the overlay contract, kept.
- **The frame is the dock's floor, not a dock member.** It never comes or goes, so it has no rank to claim in a transience-ordered column. The notification dock stacks upward from the frame's top edge; the smoke suite holds every floating member off the frame the same way it holds them off the Action Bar.
- **The button is the offer.** It is mounted if and only if the fire is legal now, so a Signature button on screen is always pressable — the same rule the Action Bar keeps by dimming a Slot that cannot fire, held one step further because this control has room to leave.
- **Untargeted Signatures only.** The button fires with a tap and carries no targeting flow; the catalog refuses a `fixed` card whose `target_type` is not `none`, so the gap is a load error rather than a latent one.
- **The earn stays visible where it happens.** A granted Charge lights its segment on the frame's resource bar and floats Board Feedback at the Hero's hex in the same beat; a wasted earn — a qualifying block at the full bank — floats in a lost tone, because overcap is the banking decision's one price and a silent waste is unlearnable.
- **Party seed, solo implementation.** The frame's shape is the first party frame — compact enough that a second could sit beside it when the multi-Hero model lands — but only the primary Hero's is built, and the board direction's per-token-state question stays deferred to that same milestone.

## Accepted costs

An Encounter without a Signature (the teaching slice) still carries the frame, minus the resource bar and the button — persistent chrome the first-turn script does not yet teach. A first-time player also meets the button with no warning the first time it arrives, since nothing on screen rehearses it beforehand; the resource bar filling toward its cap is the only foreshadowing, and whether that is enough is a play-feel question this ADR cannot answer. The Hero's health moved out of the tap-a-piece vocabulary, so the first tile a new player taps (their own) now answers with a pulse instead of a panel; the frame being permanently present is what makes that answer readable. And ~60 points of the board container's spare height are now spoken for on the smallest supported phone — the resource bar rides inside the health gauge's existing 44px tap target rather than stacking a second one, which is what keeps that number from growing — the direction doc's fit table is stale on this and the Stat Panel rows and needs its next measurement pass.
