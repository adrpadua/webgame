# Draw the Boss Program order from the seed

A Boss's authored `boss_programs` list is a **pool**, not a script. The order it runs them in is a `programSequence` resolved once, at encounter setup, from the encounter seed. Index `0` is pinned to the authored first program; everything after it is dealt from repeatedly shuffled bags of the whole pool. `advanceProgram` walks a cursor into that resolved sequence, and `nextProgramId` — the Forecast Row's lookahead — is a plain array read one step ahead.

The problem was that `programIndex = (programIndex + 1) % programIds.length` made the third timeline horizon decorative. ADR 0026 spent a Forecast Row on disclosing next Round's whole program a Round early, but under a fixed rotation the next program was deducible from the Round number alone: on Embermaw, Phase I was `hunt, embers, brood, hunt, embers, brood`, forever, on every seed. A player learns that in Round 2 and never reads the row again. Measurement made it concrete — with the player passing every window, the Round-by-Round program sequence was byte-identical across five unrelated seeds, so the only randomness reaching the player was the deck shuffle.

**The order is rolled at setup, and that placement is the whole design.** ADR 0025 forbids resolving rules randomness after the window that answers it, and the Forecast Row shows next Round's program a full Round before it resolves. Rolling at the Round boundary would therefore be a direct violation: the row would have to display a value that had not been decided yet, or the roll would have to happen a Round early and be stored — which is this decision, arrived at by the longer route. Setup is the only placement where nothing about the Boss's plan is undecided once any window is open. It also means Phase II's order is rolled at setup rather than at the Phase Break, because a break is reached mid-fight and would otherwise resolve randomness after the row had already needed it.

**Round 1 stays authored.** The opener is the teaching Round, and it is the one Round the Forecast Row can structurally never have disclosed — ADR 0026 records that hole honestly. Pinning index `0` keeps the author in control of the fight's first impression and preserves the existing rule that the first program must carry no `severe` Beat. Phase II inherits the same treatment for the same reason, which is why `phase_two_programs` is now an ordered list whose first entry must also be `severe`-free: Embermaw's was reordered to `ashfall, molting` so the Phase Break does not open on a priced Brood Call.

**Bags, not independent draws.** Shuffling the whole pool and dealing it out keeps each program appearing about as often as the fixed rotation did, so this changes *when* a demand lands without changing how much of it a fight contains. Independent per-Round draws were rejected for exactly that reason: they would have made program frequency a random variable, so a run could face three Brood Calls in a row and the change would have been a difficulty change wearing a variety change's clothes. A no-back-to-back-repeat rule rides along, applied only to pools of three or more — with two programs the rule stops being a safeguard and forces strict alternation, removing the variance the mechanism exists to add, which is why Phase II's two-program pool may legitimately repeat.

Two alternatives were rejected. Authoring more programs would have addressed the symptom at the highest possible content cost, and does nothing about determinism: six authored programs in a fixed cycle are still fully predictable by Round 7. Randomizing which *Beats* a program contains was rejected because it destroys the Forecast Row's contract — the row promises a program's family-level shape a Round early, and a program whose contents are unknown has no shape to promise.

The accepted cost is that seeded fixtures move. Every committed Scenario regenerated, and tests that reached Whelps by advancing to Round 1's Incoming Row had to ask for a seed that schedules a Brood Round instead. That churn is a one-time price and it exposed a real fixture defect: a jump-point Scenario named for Round 3 was asserting a Brood Call that only landed there by rotation accident, and now cuts on the property it actually wants — Whelps standing on the board.

Acceptance is stated structurally, in the shape ADR 0027's correction argued for rather than as percentages that decay when someone tunes damage:

- Round 1 is the authored opener on every seed, and the first program of every phase carries no `severe` Beat.
- Different seeds produce different orders, and every three-Round window contains each Phase I program exactly once.
- No program repeats back to back while three are available.
- Advancing a Round never changes `programSequence`, only the cursor into it — the property that keeps the Forecast Row a read rather than a roll.
- The sweep's `roundSpread` column is not a single value for any policy. Under the fixed rotation, twelve of eighteen policies ended on exactly one Round across thirty seeds; that column exists so the failure is visible in the default table instead of hiding inside an average.
