# Rebuild the Encounter Engine in TypeScript as the rules source of truth

The Encounter Engine moves to TypeScript in a `web/` Vite workspace, and that implementation becomes the source of truth for game rules. The rules documents — `CONTEXT.md` and `docs/rules/` — are the specification it implements; where the frozen GDScript engine and the documents disagree, the documents win, and a divergence from GDScript behavior is a defect only when it contradicts them. The Godot codebase is frozen: no further Godot work, with the code kept in-tree as the behavioral reference until the web Embermaw slice reaches parity. The first consumer is the Encounter Workbench, the browser surface that presents the portrait play surface in a desktop frame with debug tooling (scenario picker, time travel, fact log, seed control) in the surrounding space.

The TS engine is a pure reducer: `resolve(state, action)` returns the next immutable state plus the Resolution Facts and lifecycle facts produced. This is a translation, not a redesign — ADRs 0007, 0009, 0013, 0014, 0015, and 0017 already made the GDScript engine a headless, node-free state machine where every mutation rides an action record, legality is a public predicate, and the board has one authority. The reducer form keeps those decisions and makes their payoffs structural: deterministic replay is a fold over the action log, a Scenario is a named seeded action prefix (never a state snapshot, which can encode impossible states and rots when the state shape changes), headless simulation is a loop in Node, and time travel is free. Rendering splits along the same seam: Phaser owns only the hex board canvas, rendering engine snapshots and reporting hex-level intents, while React owns the hand, Action Bar, HUD, and debug panels — Phaser never owns game state. Engine purity is enforced by a lint rule (no `react` or `phaser` imports under the engine directory) rather than package boundaries, which stay collapsed until a second real consumer exists.

Seeded randomness (ADR 0012) carries over, including the per-call audit trail, but numeric parity with Godot's PCG32 is explicitly not a goal: the TS engine uses its own well-known seeded PRNG and records fresh baselines. Consequently Encounter Records move to `schema_version: 2` — the envelope concepts survive (seed, submitted/generated/rejected actions, Resolution Facts, content fingerprint, initial/final snapshots, axial `{ "q": number, "r": number }` hex encoding) but field shapes follow the TS state model, and version 1 records remain readable history rather than a compatibility target. Web tests run standalone in Vitest via `npm test`; the probe manifest (ADR 0018) gains a third adapter only when unified CI needs one command.

The trade-off is deliberate: Godot's editor, export targets, and the working Embermaw slice are set aside in exchange for the iteration loop the prototype phase actually needs — hot module reload on rules and UI changes, jump-to-state Scenarios instead of replaying from Round 1, DOM-inspectable interaction surfaces that agents can read and drive, and a rules core that unit tests and headless runs exercise directly. The rejected alternatives were a disposable parallel sandbox (drifts from the real rules and its findings die with it), a faithful port that treats GDScript behavior as the spec (launders implementation accidents into the new source of truth), and maintaining both engines (two sources of truth). Delivery is staged: M1 a playable core loop in the browser, M2 Embermaw parity with the scenario harness, M3 record emission, deterministic replay, and a headless runner.
